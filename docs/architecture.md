## 一次刷新怎样经过程序

1. 前端发起请求，server.mjs 校验输入并建立刷新任务。
2. 刷新逻辑读取本地保存的基金列表、披露持仓和已有结果。
3. provider、indices 等模块获取或复用基金资料、行情及汇率。
4. calendar 和日期规则确定模型对应的基准、目标与收盘状态。
5. 股票、指数或债基模型计算参考结果，同时记录覆盖率和缺失原因。
6. 保存原始输入与预测证据；正式净值到达后按日期配对核对。
7. PostgreSQL 保存变动记录，前端显示结果、进度和错误。

建议从 `public/index.html` → `public/app.js` → `server.mjs` → 对应业务模块阅读；再用同名或相关测试理解边界情况。项目没有前端打包步骤，可直接比较浏览器模块与源码。

## 估算为什么会有误差

股票模型使用公开披露权重与对应市场收益，结合相同估值区间的汇率。披露之外的资产、调仓、费用和基金真实汇率口径未必完整可知；已取得的股票也不重新归一到 100% 来伪装完整组合。

指数基金采用对应指数和汇率的近似模型。债基保留原三指数模型 `bond-fit-v1`，新增持仓约束模型 `bond-fit-v2`：同步债券持仓时补充季度报告的券种配置和公布日期，以净值占比作为非负岭回归的软先验，结合中债分期限国债、政策金融债、信用债、中票和存单财富指数。持仓不是实时明细，前五大债券不放大为整个组合；超过100%的债券敞口保留，截距是残差而非另加票息。

新版使用此前30个净值日逐日比较不同窗口与正则强度，每一日仅使用当时已公布的季度报告和更早净值。总体平均绝对误差须较原模型降低至少5%，最大误差不超过原模型的1.1倍，最近10次误差不超过原模型的1.05倍，才采用新版，否则保留原模型。目标日中债收盘序列尚未齐全时等待，不提前封存旧模型；网络失败可降级为原模型并说明原因。新旧封存记录和准确性统计独立，滚动选择结果不等于未来成绩。模型缺数据时应说明原因，不能填零或补造历史预测。

2026-11-03 新增稳定组合候选 `bond-fit-v3`：保留8项既有财富因子，不增加未经核实的新数据源；以训练期内各因子的中位数和MAD衡量极端输入，对超过3个稳健尺度的样本按平方比例降权，保留原始样本及超过100%的披露敞口。组合160日/60日半衰期、90日/30日半衰期和160日等权三组非负岭回归，系数取均值。最近30个逐日重建样本分为前20日选择、后10日独立确认；两段均须较前20日选定的v2对照降低至少5%平均绝对误差、最大误差不超过1.1倍。还须在全30日较v2最优候选降低至少5%平均误差，最大误差不超过1.1倍，最近10日平均误差不超过1.05倍，并满足相对原三指数模型的既有门槛。没有通过就继续选择原v2或按原规则回退，不因昨日单日结果强制采用新公式。v3保存成员系数及确认窗口，支持独立回放与分模型准确性统计。

有足够30日验证样本时新增绝对误差保护：所用候选的平均绝对误差超过0.03个百分点、最大误差超过0.10个百分点，或稳定组合成员预测分歧超过0.10个百分点，结果仅作“低可信参考”，暂停生成新的正式封存预测；在已具备验证误差时回退原模型也接受此保护。上述值为工程默认门槛，不代表基金收益风险上限。缺少完整验证时的既有取数回退逻辑保留。详情显示以历史绝对误差90%分位和成员分歧一半取较大者形成的对称参考区间；它不是统计置信区间，也不保证未来覆盖率。旧封存记录不套用新增字段门槛，不补造或改写历史预测；刷新只对后续可生成的新预估生效。

2026-11-03 进一步增加 `bond-fit-v4` 超长债配置候选，直接改进预测公式的先验：同一报告期已披露、名称明确为超长特别国债的持仓净值占比，分配给30年国债财富指数软先验；剩余国债沿用短债与7—10年国债分配。仅使用持仓截至日与季度配置一致、报告已在目标日前公布、合计不超过季度国债占比的明细；不放大前五大持仓，不将30年代理解释为每只持券的精确剩余期限。无有效线索时原方法不变。候选此前30日逐日验证的平均绝对误差须低于原v2最优候选，最大和最近10日平均误差均不得增加，还须满足相对v1的既有门槛，才采用。参数窗口和正则强度沿用既有三组配置。保存期限线索、对照误差及所用参数以支持独立回放与分方法统计；已有误差保护继续生效。同步时保存有限报告期的期限线索，同期撤回或更正时移除旧线索。

研究误差时应区分：

- 使用当前持仓回看过去的解释性计算。
- 正式净值公布前已保存且日期有效的预测样本。
- 正式净值公布后才得到的结果。

只有符合项目证据规则的样本才能用于事前估算核对；历史净值条数不等于预测样本数。

## 存储与兼容代码

正常运行使用 PostgreSQL。业务记录和大输入快照分离，大快照压缩并按哈希共享；运行日志、行情缓存和应用备份也入库。

Store 及部分文件维护工具保留旧 JSON 格式，用于导入、历史兼容和测试。它们要求工程目录以外的显式数据路径，不代表正常模式会自动回退到 JSON。

`scripts/cleanup-*`、归档、压缩及恢复工具用于特定维护任务，不是首次安装所需步骤。学习时先读代码与参数，在自己的副本和临时数据上验证后再考虑使用。

## 推荐练习

1. 运行模拟预览，找到一张卡片对应的前端渲染函数。
2. 选择一个模型纯函数，阅读关联测试并手算简单输入。
3. 跟踪一次刷新任务的进度状态，理解重复请求复用逻辑。
4. 在副本中加入一个人工构造的缺行情场景，观察错误提示。
5. 阅读 PostgreSQL 表结构，比较轻量记录与输入快照的关联。
